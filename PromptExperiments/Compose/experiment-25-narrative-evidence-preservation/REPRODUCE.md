# Reproduce

Use the baseline commit in `model-configuration.json`, Windows, the installed .NET 10 SDK, Node 22, the production machine-local OpenAI credentials and authenticated GitHub Copilot. Set `EXP25_COPILOT_LOADER` only if the standard npm path in the runner differs. Keep the checkout's production prompt line endings consistent with the recorded hashes. Build the solution before generating.

In this archive run `node verify.cjs` and `node gates.cjs` from the experiment directory or call them by path from the repository root. The verifier checks immutable inputs, both checkpoint files, all frozen handoffs, exact reference reconstruction and unchanged production prompts. The analyzer validates request and output links, checks Compose payloads, and derives subject-grouped metrics from raw results. It recognizes the Experiment 23/24 named editorial dimensions and standard factual labels with descriptions. It also recognizes `bodyExcerpt` as an alias for `excerpt` and requires the same exact text validation. Raw invalid statuses remain in operational counts. Use `node inspect.cjs` to derive claim-level omission and historical anchor excerpt files.

To produce a new sample, use a separate copy with the frozen inputs and empty generation and review folders. Preserve the archived inventory and its operator source checks. Generate development through `node runner.cjs development`, retain the confirmed candidate checkpoint, then run `node runner.cjs holdout`. Check historical stress claims and adjudicate by output before using the results. `node adjudicate.cjs development` and `node adjudicate.cjs holdout` produce fresh, independent evidence adjudications after analysis. The output owners and conditions are outside the model request. Reviewer raw output and failed reviews stay in the archive. Do not reuse decisions from this sample for a different one.

The original runner and inventory freeze are retained for audit. The supplement was a one-time reviewer-only correction before holdout. To reconstruct that part use the archived original version and source records, and preserve the originally returned review texts. Model/provider defaults can yield different outputs and raw API response bodies and usage are unavailable to the production path.

The original Digital, Webb and Wolf replay envelopes used PascalCase Idea properties, which the current CLI rejected before calling the model. The archived errors and exact originals are retained under `recovery` and `fixtures`. The final runner uses the frozen casing-normalized envelope for both A and B on these three cases. The verifier compares all field values with the originals. For a new run using the canonical envelopes, the deliberate reproduction of these known pre-model errors is unnecessary.

The independent factual review could use one bounded coverage pass after both first and second audits failed full validation. `node coverage.cjs narrative holdout` and `node coverage.cjs article holdout` replay just the still-missing review slots. Coverage artifacts are separate from the original attempts and use the same stage, evidence and meaning rubric. The recovery-only Narrative reviews used `node review-recovered.cjs`. Neither command regenerates content.

For this sample, run `node analyze.cjs`, `node inspect.cjs`, `node audit-anchors.cjs`, `node merge-adjudications.cjs`, `node verify.cjs`, `node gates.cjs`, then `node render-results.cjs`. Review the source-backed operator files alongside the raw labels. The claims correction file records the specific inventory judgments where exact text or source evidence required adjudication. Keep both the raw and corrected values in a new sample.
